# Phase 1.15 — Expandable SDF Volumes: architecture record

Status: the bounded rectangular dense implementation and live integrations were completed in Phase 1.15 on 2026-10-26; physical Quest acceptance remains pending. See [implementation, results and checklist](VR_EXPANDABLE_VOLUMES.md). The text below records the preceding architecture investigation and its milestone rationale. The formerly deferred Phase 3.1 bounds work is now implemented with finite safety budgets; sparse storage and cooperative scheduling remain future work.

## Current finite storage and behaviour

`SDFVolume` is a cubic, dense Float32 grid with a same-size Smooth scratch array. The default extent is 1.6, so each layer owns local bounds [-1.6,+1.6] on every axis (3.2 units across). Samples include both ends; h = 3.2/(n-1), not 3.2/n. New/explicitly resampled layers offer 64³, 128³ and 192³. Changing resolution currently resamples the same bounds and clears that layer's voxel history; it is not expansion.

| Samples | Local spacing h | Grid MiB | Grid + scratch MiB | Worst unique-index action payload MiB |
| --- | ---: | ---: | ---: | ---: |
| 64³ | 0.050794 | 1 | 2 | 3 |
| 128³ | 0.025197 | 8 | 16 | 24 |
| 192³ | 0.016754 | 27 | 54 | 81 |

History payload estimate is 12 bytes per changed voxel (Uint32 index + before/after Float32); pending JS Maps, staging patches, array growth copies, geometry, CSG caches, exports and GPU allocations are additional. Latest history action can exceed the soft 32 MiB layer budget. Native aggregate cap is 2×192³ samples, including hidden sources; eight layer records maximum. Those are capacity limits, not guaranteed Quest memory headroom. Dense doubling on all axes multiplies samples by eight: a doubled 192³-equivalent source needs 432 MiB for grid+scratch alone, before transactional peak allocations.

Layer metadata TRS maps local bounds into project coordinates; actual brush conversion also inverts tracking, workspace and sculpture parents. Rotated boxes have an enclosing world AABB that is larger than the oriented volume. Uniform layer scale s gives project voxel spacing h*s. Navigation scale w changes the apparent physical spacing to h*s*w, without modifying stored samples, resolution or metadata. Nonuniform editable-layer scaling remains unsupported. Tool-tip reach is physical 12 cm and independent of navigation zoom.

The UI brush radius range is .12–.5 project units, converted to local radius by dividing by layer uniform scale. A radius-sized brush can touch the boundary before its centre does. Boundary samples are forced positive. Near-boundary strokes warn and may be clipped; once the free-space centre leaves the cube, the XR adapter cancels and exactly rolls back the unfinished stroke. Already finished strokes remain. Previously clipped detail cannot be reconstructed by a future expansion algorithm.

Add stamps whose rotated conservative bounds reach the one-voxel safety margin are rejected before any write; they are not silently cropped. Subtract stamps may overlap bounds and affect only stored material. Prepared stamp CSG can change positive far-field distances across most of the dense grid even when its visible shape is small. This drives staging/history cost as well as kernel work.

Composition reads transformed independent sources through inverse transforms and a positive exterior extension. The disposable composite grid attempts to match finest project spacing but is capped at 192³; distant/large source extents can lower derived detail. Explicit Bake samples a new padded, normalized cubic source at chosen 64/128/192 resolution. Sources stay independent; Bake may lose fine details, has aggregate capacity checks, cancellable preparation and one timeline action. Separate GLB flattens source chunk geometry; Boolean GLB flattens the derived result. Helpers live outside exports.

## Recommendation and trade-offs

Adopt a **stable signed integer lattice per layer**, with immutable voxel spacing and local lattice origin, and separate allocated bounds from the layer transform. Use a budgeted rectangular dense implementation as the first reviewable milestone, while making the interface and history coordinate-safe for a later sparse backend. Do not just enlarge `extent`, stretch layer scale, or call `resampleVolume`: all three alter detail/spacing or geometry placement.

| Design | Advantages | Costs / constraints |
| --- | --- | --- |
| Rectangular dense growth | Exact copy; straightforward existing brush/interpolation adaptation; easier native compatibility and transactional validation | Cubic memory growth in long diagonal drawings; whole-allocation peak on growth; capacities must reject impossible requests |
| Sparse chunked lattice | Allocate near new work; long free-space strokes scale with touched regions; stable chunk keys and local history | New halo/interpolation/Smooth semantics, implicit exterior field, far-field CSG evaluation, save format and memory eviction complexity |

Sparse is the likely long-term backend for open-ended VR drawing. A dense interim is acceptable only with explicit memory ceilings, atomic rejection and no claim of unlimited volume. An immediate sparse engine rewrite would combine too many correctness risks. Choose the sparse transition after measured dense-growth traces on Quest, not an arbitrary fixed number of phases.

## Concrete implementation plan

1. **1.15a — coordinate and compatibility foundation.** Introduce explicit `dimensions:[nx,ny,nz]`, lattice allocated min/max and fixed spacing, plus per-axis sample coordinates (current `coordinate(i)` assumes the same axis origin). Keep layer TRS unchanged. Audit every `resolution³`, `%n`, stride, boundary, memory, brush, history, normal, mesher, compositor, Bake and native loop; `VolumeStore` already separates storage but callers still assume cubes. Legacy cubic adapters remain readable. Ship exact baseline tests before enabling growth.
2. **1.15b — history identity before resizing.** Replace retained flat-index assumptions with stable lattice coordinates/chunk keys, or explicitly bind every voxel action to a store-generation snapshot with verified remapping. Prefer stable coordinates. Expansion is part of the triggering stroke/stamp transaction: the implemented policy retains harmless expanded capacity on Undo/cancel while restoring exact voxel values; Redo reproduces the edited values within that capacity. Redo payloads must not alias live buffers. Freeze project/layer/store identity through asynchronous preparation; interruption/lock/role changes abort without mutation. Do not commit history before new buffers and geometry are ready. Account for retired stores held by undo/redo.
3. **1.15c — growth planner and atomic dense migration.** Compute the union of current allocation and predicted brush/stamp footprint plus interpolation, gradient, Smooth and one positive-boundary halo. Convert through the full inverse layer/world chain. Round growth outwards to stable 16-cell chunk boundaries, separately on each negative/positive axis. Grow before editing boundary samples. Preserve every old Float32 bit at its original local coordinate; never translate the object or change spacing. Initialize new exterior with a defined positive field continuous with the old positive boundary; use positive boundary extension plus distance, saturated under the agreed distance contract. Old clipped surfaces remain clipped. Reject invalid/oversized plans before writes. Preallocate/copy/yield with progress and cancellation, then atomically publish the store/history/mesh bundle. At the hard memory ceiling, explain the blocked edit and retain the original project.
4. **1.15d — stable mesh chunk indexing.** Replace linear chunk IDs tied to axis count with signed (cx,cy,cz) keys anchored to the lattice. Preserve chunks and geometry away from growth faces. Invalidate new cells and neighbouring gradient/Smooth halos; extraction cells must have one owner across chunk borders. Update surface selection bounds revision on store swap and geometry updates. No positional jumps or stale cached selection boxes. Test seams and normals through growth on all six faces/corners.
5. **1.15e — native v4.** Store dimensions, spacing, lattice allocation/origin, backend tag and validated Float32 payload/chunk directory. Retain v1/v2/v3 readers by mapping their cubic extent into the lattice exactly. Add independent byte/sample/triangle budgets, overflow-safe strides and untrusted file validation. Do not emit v3 files containing noncubic data or silently downsample to fit them. Make legacy export an explicit, warned conversion if ever offered. History need not be serialized unless a separate feature is approved.
6. **1.15f — CSG, Bake, export and UI.** Generalize samplers to rectangular/possibly sparse bounds with a defined positive exterior. Composite bounds follow allocation, but distinguish occupied bounds to avoid unnecessarily reducing preview detail. Expose quality-cap warnings; no source mutation. Bake remains an explicit resampling operation and must report its output spacing/detail limit. Both GLB paths consume updated geometry with stable transforms. Show allocation/budget and progress in existing UI; input stays reserved during migration. Add redo-safe growth cancellation and source-isolation tests across transformed overlapping layers.
7. **1.15g — Quest acceptance and sparse decision gate.** Measure peak grid+scratch+history+staging and browser heap where available, stall duration and chunk latency for growth in ±X/±Y/±Z, long diagonal strokes and repeated stamps at every starting resolution. Define a measured safe project memory budget and copy batch size on Quest 3. If dense growth fails practical drawing targets within that budget, implement a sparse store behind the same lattice contract. Use signed chunk keys, consistent one-cell sample sharing/halos, lazy scratch regions and copy-on-write history; evaluate implicit positive exterior and lazy CSG operations rather than materializing huge far fields.

## Acceptance gates before enabling expansion by default

- Existing samples and features bit-exact after every growth direction; same local/world positions and spacing through rotated/scaled layers and workspace navigation.
- No gaps at old/new chunk faces, interpolation or normal seams; max-radius and Smooth footprints have sufficient halos.
- One user action remains one exact undo/redo, including expansion; interrupted/cancelled preparation leaves native bytes, layer metadata, redo and live geometry unchanged.
- Legacy native files load identically; v4 malformed dimensions, overflow, duplicate/missing chunks, NaN and memory bombs reject before publication.
- Hidden/locked/independent sources, layer switching, controller loss, menu grabs, Bake cancellation and both export paths retain their invariants.
- Hard-budget refusal is predictable and actionable. No silent resampling, automatic layer merge, or loss of prior detail.
- Quest 3 timings and peak allocations recorded separately from Node/browser results. Automatic Add growth is now enabled with hard storage limits; physical acceptance and responsive cooperative scheduling are still outstanding. Expanded Resample/v2-only save reject explicitly; v4 save/load is supported.
