## 1. Result and use

Desktop **Reference Images → Import references…** accepts multiple PNG/JPEG files. Each image has Select, Show/Hide, Lock/Unlock, attachment, confirmed Delete, numeric XYZ and XYZ degree rotation, aspect-preserving size, opacity, front/two-sided display and reset. New images start locked, placed in alternating slots beside the sculpture to avoid coincident imported planes. Size means the longest image edge in parent source units, 0.05–10; portrait images cannot accidentally become enormous backgrounds.

In XR, hold Support stick Up → World Settings → References. Select an image, Unlock, enable Edit, release the menu, then point at the **selected** image and hold Tool trigger. Moving/rotating the controller moves/rotates that panel by the controller's relative rigid transform. Release preserves placement. Size changes use −/+ menu controls with one size readout (1.1× steps); desktop fields provide exact size and angles. Flip X mirrors image UVs horizontally and persists as optional display metadata without modifying source bytes or the panel transform. More settings groups two-sided display, confirmed deletion and precise placement. Precise placement offers 0.05-unit XYZ increments, reverse face and reset. Opacity cycles 100/75/50/25 percent in VR; desktop allows 5–100%. No new Tool grip binding: Stamp attachment, Transform Layer, Tube editing and workspace grip precedence remain. Both grips still navigate/scale the whole workspace.

Only explicit Edit + selected + visible + unlocked + ray hit within 0.1–3 metres claims the trigger. Other panels have empty default raycast functions and cannot mask source picks. Existing active sculpt transactions, menus, diagnostics, alternate trigger, layer/workspace grips and tracking guards take precedence. Interrupted editing requires a fresh neutral trigger. Menus still use the Phase 4.2 canvas, 32px labels, shared scaling and large ray rectangles. References do not select tools or add history actions.

## 2. Architecture and transform contract

- Scene → workspaceRoot → reference workspace root → panel: `worldMatrix = workspaceMatrix × referenceLocalMatrix`. “Workspace” is a navigation anchor, not an absolute physical-room/world anchor. It follows Support/both-grip workspace navigation and Reset Workspace View; turntable rotation does not affect it.
- Scene → workspaceRoot → turntable.group → reference sculpture root → panel: `worldMatrix = workspaceMatrix × turntableMatrix × referenceLocalMatrix`. Sculpture attachment follows the sculpture presentation/navigation frame and its turntable pivot/angle. It is **not attached to an individual layer** and does not follow a layer's source transform or deformation.
- Switching attachment inverse-converts the current world pose to the new parent's local pose. Both parents have identical workspace scale; turntable contributes rigid motion only. Uniform size is retained.
- Reference roots are siblings of source roots, outside sculpture bounds, Boolean/Bake, SDF, source histories, export sources and controller rays. No tool kernels, source geometry algorithms, meshing or GLB exporter changed.
- Each panel is a flat PlaneGeometry with transparent MeshBasicMaterial, sRGB texture, no tone mapping, aspect preserved, optional DoubleSide. ImageBitmap is flipped at decode (WebGL unpack flip does not apply to ImageBitmap); bitmap premultiplication/colour conversion is disabled. Mipmaps remain available. No lighting dependence, camera permission or Scene.background assignment.
- Depth test stays enabled so sculpture can occlude the reference; depth writing is disabled so references do not create invisible occluders. VR menus retain their existing overlay priority. A mint edge border is offset 0.002 source units, and appears only for the selected unlocked image in Edit. No always-on handles or controller-parented images.

**XR reference-space limits:** saved coordinates are source/workspace coordinates, not tracked room anchors. Entry fits the workspace relative to the first tracked head pose; new sessions/environments may place the whole workspace elsewhere. Studio ↔ Passthrough retains the existing exit/fresh-Enter flow. References are visible in both; AR background stays transparent. Turntable stops/resets at entry/exit/project changes, so sculpture-attached references return to the saved local pose rather than preserving an unsaved turntable angle. Tracking-reference-space resets are not persistent room calibration. Hand Reference is deferred.

## 3. Persistence, safety and resources

Optional `displayPreferences.references` stores metadata plus immutable compressed Uint8Array source bytes in runtime snapshots. With assets, native **v5** uses the existing 16-byte header and bounded JSON descriptors, the normal voxel payload, then concatenated original image payloads. Descriptors contain contiguous byte offsets/lengths, MIME, dimensions and display/transform fields. Files without images still use legacy v3/v4 writers; v1–v4 readers remain. V5 supports rectangular and cubic layers. There is no base64 or external asset dependency. Old applications cannot read v5; use this version to reopen projects containing images.

Limits: six images, 4 MiB compressed per image, 12 MiB combined, 4096 per side and 4 megapixels/image. File size/count/aggregate size are checked before reading/decoding a desktop batch; imports stage atomically and check the same active project/session before publishing. PNG/JPEG signatures and frame dimensions are checked independently of names; declared nonempty file MIME must agree. Reject unsupported formats, APNG, truncated PNG structure, repeated headers, missing JPEG end, repeated JPEG frame headers, extreme dimensions, invalid enums/transforms, duplicate IDs, invalid payload lengths/offsets and trailing native bytes. Browser decode must succeed and match validated dimensions before desktop import publishes. No fetch to third-party image URLs.

Native validation is synchronous bounded header/structure validation, not a complete PNG CRC/JPEG entropy decoder. A damaged native image payload with structurally valid headers can pass native loading and fail browser decode; it remains hidden with an error in References/desktop, can be removed, and does not discard the sculpture. Only static PNG and supported JPEG frames are accepted; WebP, GIF, SVG and animation are deferred. Decoder/EXIF dimension mismatches reject rather than risk an oversized or incorrectly scaled image.

Async createImageBitmap performs decode; imports are desktop-only outside XR. GPU upload is renderer work and can still cause a first-visible-frame pause; no hard frame-time guarantee. Hidden images retain their bounded textures for quick toggling. Deleting/replacing projects, exiting XR, pagehide and HMR dispose textures/materials/geometries and close bitmaps. In-flight decode completion closes the bitmap if its panel was removed. No object URLs are created, so no URL revocation path is needed. Session exit releases XR resources; subsequent desktop rendering lazily recreates visible assets.

Snapshots clone image bytes once for isolation, then transfer snapshot buffers to the recovery worker (deduplicated transfer list). Source bytes remain live. Recovery admission adds four times compressed bytes to its conservative temporary-memory estimate. The existing IndexedDB quota/cap/last-good-checkpoint behavior remains; compressed size and approximate RGBA+mipmap GPU size are visible on desktop. The revision key includes asset identity/byte count and presentation properties, not a per-frame serialization of image bytes. App-owned bytes are immutable; changing image contents requires a new asset ID. Native size cap includes the bounded asset payload. Blob construction takes the immutable source view without an extra JavaScript slice.
